## 3. ① 문제 정의 — 쏟아지는 정보와 제한된 판단 시간

- 검색·알림 도구가 있어도 출처를 넓게 봐야 한다. 정책결정자·기업 경영진이 Truth Social이나 X에 먼저 소식을 올리기도 한다.

- **판단의 병목:** 소식을 포착한 뒤 사실인지 확인하고 내 투자 근거에 미칠 영향을 판단해야 한다.

## 4. ② 서비스 제안 및 차별성 — 질문에 답하면, 내 업무에 맞춘 에이전트가 만들어진다
운용역은 설계하지 않는다. AI Agent가 인터뷰로 초안을 만들고, 운용역은 고치고 승인만 한다.

**인터뷰 장면 (예시: 반도체 담당 운용역)**
1. 운용역의 요청: "출근 전에 내 종목 소식만, 내 투자 근거 기준으로 정리해 줘"
2. AI 인터뷰
   - Q 관심 분야와 투자 근거는? → A 반도체·AI 인프라 (근거: 빅테크 AI 투자)
   - Q 언제 정리해 드릴까요? → A 매일 07:30, 또는 '지금 조사해'
   - Q 급한 소식은 얼마나 자주? → A 5분이면 충분, 장중엔 1분
3. 나만의 에이전트(초안): 대상 NVIDIA·Micron 등 8개사 · 검색어 capex·가이던스·수출 규제·HBM · 출처 SEC 공시 + SNS·블룸버그(확장) · 정리 매일 07:30, 즉시 경보 5분 · 비용 공시 확인 무료, AI 판정 건당 $0.04(Claude Opus 5.5 기준, 2026.11 시험 판정) → 운용역 [수정] 또는 [승인] → 이때부터 가동

**차별성**
| 원문으로 확인되는 근거 | 묻지 않아도 먼저 움직인다 | 답만 하면 되는 개인화 | RSI + 사람 최종 승인 |
|---|---|---|---|
| AI 답을 원문과 맞춰 보고, 원문에 없으면 버림 → 할루시네이션 차단 | 챗봇은 물어야 답한다. 에이전트는 5분마다 스스로 확인, 07:30 정리 | 질문 3개에 답하면 대상·검색어·주기 초안이 완성 | 놓친 사건 → AI 수정안 → 🔒 사람이 승인해야만 반영 |

## 5. ③ Agent 역할 및 Workflow — 수집은 프로그램 코드가, 판단은 AI Agent가, 결정은 사람이
프로그램 코드가 AI 토큰 없이 계속 지켜보고, 관련 소식이 있을 때만 AI Agent가 근거를 찾아 판정한다.

| 단계 | 담당 | 내용 |
|---|---|---|
| ① 설정 | 사람 | 인터뷰로 근거·주기 |
| ② 수집 | 프로그램 코드 | 5분마다 새 소식 |
| ③ 선별 | 프로그램 코드 | 내 키워드 관련만 |
| ④ 근거·판정 | AI Agent | 부족하면 다시 검색 |
| ⑤ 검증 | 프로그램 코드 | 인용·금액 원문 대조 |
| ⑥ 보고 | 프로그램 코드 | 즉시 또는 07:30 |
| ⑦ 확인 | 사람 | 동의 / 불필요 / 보류 |
| ↺ RSI | AI Agent → 사람 | ⑧ 놓친 사건 원인 분석 · ⑨ 검색어·출처·주기 수정안 · ⑩ 🔒 운용역이 승인해야만 ①에 반영(되돌리기 가능) |

**결과물: 07:30 판정 보고서(예시)**
- [재검토 필요] 내 투자 근거 「수출 규제 영향은 제한적」이 흔들릴 수 있음
- 사건: NVIDIA, H20 칩 중국 수출에 허가 필요 (수시 공시 8-K, 04.16 06:22)
- 근거: "…up to approximately $5.5 billion of charges…" ✓ 원문 일치
- 수치: '최대' 55억 달러 예상 — 실제 비용은 아직 미확정
- 다음: 분기 보고서(10-Q)에서 실제 비용 확인 · 운용역 [동의] [불필요] [보류]

## 6. ④ AI 기술·Tool/API 구성 — Hybrid RAG 기반 검색에 API를 더하고, RSI로 개선한다
단어와 뜻, 두 방식으로 원문을 찾는다. 놓친 사건은 AI Agent가 원인을 분석하고, 사람이 승인해야 고쳐진다. 외부 AI에는 공개 자료만 보내고, 보낸 내용은 모두 기록한다.

**① Agentic Hybrid RAG** — 키워드 검색(BM25: 'H20'·'Item 4.02' 같은 정확한 단어) + 의미 검색(벡터·임베딩: '수출 규제' ≈ 'export license') → 순위 결합(RRF) → AI Agent 판단(충분 → 판정 / 부족 → 검색어·출처를 바꿔 다시 검색, 최대 2회)

**② RSI + 🔒 사람 최종 승인 — 실제로 해 본 결과(2026.11.9)**
- 시험 문제: NVIDIA 분기 보고서(2025.5)에서 'H20 칩 실제 비용 45억 달러'를 찾아낼까?
- ① 놓침: 비용 때문에 앞 4만 자만 읽어, 바로 뒤 '45억 달러'를 놓쳤다
- ② AI Agent 분석: 판단 실수가 아니라, 읽는 범위를 앞에서 자른 게 문제
- ③ AI Agent 수정안: 읽는 양은 그대로, 중요한 단어 주변만 골라 읽자
- ④ 🔒 운용역 승인: 승인해야만 적용 + '전체 읽기와도 비교하라' 지시
- 결과: 원래 방식 ✗ 못 찾음 $0.10 · 전체 다 읽기 ✓ 찾음 $0.24 · 골라 읽기(수정안) ✓ 찾음 $0.07 (Claude Opus 5.5 기준 실측, 사례 1건)

**③ 도구·API**
| 도구 | 하는 일 | 언제 |
|---|---|---|
| SEC EDGAR API | 새 공시 목록과 원문 가져오기(초당 요청 한도 준수) | 5분마다(장중 1분) |
| 하이브리드 검색(SQLite·임베딩) | 질문에 맞는 원문 문단과 위치 반환 | 근거가 부족할 때 |
| AI 판정 API(외부·사내 AI 교체형) | 투자 근거별 판정을 정해진 형식(JSON)으로 | 관련 사건이 있을 때 |
| 검증기(프로그램 코드) | 인용 원문 대조·금액 단위 확인·판정 기록 위변조 방지(해시) | 판정 직후 |
| 외부 데이터 연결(확장) | 기관이 계약한 피드를 붙여 쓰는 연결 규격(출처는 7장) | 기관 도입 후 필요할 때 |

## 7. ⑤ 데이터 활용 계획 — 속보는 빠르게, 정확한 팩트는 공시 원문으로 확인
출처마다 역할이 다르다. MVP는 누구나 쓸 수 있는 SEC 공개 데이터로 만들고, 기관이 계약한 피드(예: 블룸버그)는 외부 데이터 연결로 붙여 쓴다.

| 투자 근거 목록 | 인터뷰로 정한 내 투자 근거와 '무엇이 나오면 다시 볼지' | 판정 기준 | 운용역이 바꿀 때 | MVP |
