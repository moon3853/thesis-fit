## 0. 원래 아이디어(실시간 뉴스 추적)는 어떻게 바뀌었나

- **처음 하려던 것:** 뉴스를 실시간으로 추적해서, 필요한 정보가 뜨면 바로 피드백(알림)이 오게 하는 에이전트.
- **메인으로 내세우기 어려웠던 이유 세 가지**
  1. **저작권·라이선스:** 블룸버그·로이터 같은 실시간 뉴스는 유료 계약 데이터라 대회 규칙("사용에 제한이 없는 데이터")에 걸린다. 무료로 깨끗하게 쓸 수 있는 GDELT는 제목·링크만 주고 약 15분 단위 갱신이라 '실시간'이 어렵다. 기사 본문 저장·분석도 매체별 약관 문제가 있다.
  2. **시간대:** 감시 종목 8개사의 최근 1년 공시 136건 중 75%가 한국 시간 밤·새벽, 70%가 05~07시에 들어왔다. 사람이 자는 시간에 즉시 알림을 보내도 바로 판단할 사람이 없다. 그래서 "판단 시각(출근 전)까지 내 기준으로 정리돼 있느냐"를 주지표로 바꿨다. (이 숫자는 공시 기준이며, 뉴스 전체가 밤에 몰린다는 뜻은 아니다.)
  3. **블룸버그 단말기가 이미 해 준다:** 키워드 알림·속보 요약은 블룸버그로 받을 수 있어 "더 빠른 뉴스 알림"으로는 차별점이 없다. 그래서 블룸버그가 못 하는 것 — 공시가 내 투자 가정 중 무엇을 건드리는지 연결, 예상 상한과 실제 계상액 구분, 원문 근거 검증, 판정 기록·사후 채점 — 을 내세웠다.
- **원래 아이디어가 남아 있는 곳**

| 원래 원했던 것 | 최종 기획서에서 |
|---|---|
| 실시간 감지 + 바로 피드백 | **즉시 경보 등급**으로 유지(8-K 4.02 같은 치명적 공시는 15분 안에 알림). 단, 주지표가 아니라 보조 지표 |
| 뉴스 추적 | MVP는 공시만. 뉴스는 **확장 단계**(GDELT, 소문 판별) |
| 가장 빠른 출처 잡기 | "먼저 들어온 출처로 카드 생성" 구조 유지. **출처 연결부**에 KIC가 계약한 블룸버그 피드를 꽂으면 실제 도입 시 실시간 뉴스까지 확장 |

> 한 줄 요약: 실시간 뉴스 추적은 라이선스 때문에 대회 데모에선 못 쓰고, 속도만으로는 블룸버그와 차별점이 없다. 그래서 '빨리 알려 주기'는 치명적 사건(즉시 경보)에만 남기고, 메인은 '판단 시각까지 내 가정 기준으로 정리'로 바꿨다. 실제 도입 시 블룸버그 피드를 꽂으면 실시간까지 확장된다.

## 1. 주제 선정 과정 — 검토했다가 메인에서 뺀 안들

### 1-1. 투자 논지 감시·판독 에이전트 (기획서 v1)
- **하려던 것:** 운용역이 자는 동안 해외 시장을 감시하고, 급락 원인을 A~D(논지 훼손·공포 전염·수급·매크로)로 판독해 아침에 보고. 판정을 결과 전에 기록하고 D+10·D+20에 채점.
- **기각 이유:**
  - 판독은 일종의 예측이라 **AI가 과거 사건의 결말을 이미 알고 있는 문제(사후 지식)**로 과거 재현 성적이 오염된다.
  - 판독이 틀릴 수 있다(팀의 모의 선물 AI가 11/6에 4전 4패).
  - KIC의 실제 포트폴리오를 알 수 없다.
- **지금 상태:** 친구 안에 흡수. '판정 봉인·사후 채점', '사람 판단 먼저', '급락 원인 분류' 아이디어가 최종안에 들어갔다.

### 1-2. Alpha Auditor (알파 감사관, 기획서 v2·v3)
- **하려던 것:** 운용사 제안서·리포트·하우스 뷰의 "이 전략은 통한다"는 주장을 데이터 감사(수정주가·분할·시점·생존편향) + 통계 감사(무작위 기준선·다중검정·PBO·DSR)로 검증.
- **근거로 쓰려던 것:** 팀이 직접 검증한 투자 가설 20개 중 14개가 우연과 구분 안 됨, 실제로 잡은 데이터 오류(셀트리온 수정주가 누락으로 백테스트 +37.6%→+28.3% 등).
- **메인에서 뺀 이유:** 팀 논의로 친구 안을 메인으로 결정. 또 **KIC가 위탁운용사에게서 실제로 백테스트를 받아 검증하는지 확인하지 못했다.**
- **지금 상태:** 파일 보존(`KIC_기획서_v2·v3_AlphaAuditor`). 확장 아이디어로 재사용 가능.

### 1-3. 그 밖에 검토한 주제 (약 20개 중 주요 기각)
| 주제 | 기각 이유 |
|---|---|

## 4. 남아 있는 한계 (심사에서 물을 수 있는 것)

### 평가·표본
- **감시 기간 표본이 작다.** 11/12~12/22 약 28거래일, 작년 같은 기간 8개사 공시 11건, 실적은 3건(NVIDIA·Broadcom·Micron). 결과를 n/N으로 보고하기로 했지만 통계적 결론은 어렵다.
- **변형 공시 30건(실제 3 + 시연 3, 각 변형 5)**은 재심사 예시 규모를 그대로 적은 것이다. 본선 일정에서 실제로 만들 수 있는지 팀 확인이 필요하다.
- **사후 지식 문제는 완전히 풀리지 않았다.** 시연 사례(2025년 H20)는 모델이 이미 알 수 있다. 변형 공시와 실제 감시 기간 기록으로 보완할 뿐이다.
- **즉시 경보(8-K 4.02·2.06)는 기간 내 실제로 안 나올 가능성이 높다** → 주입한 가상 공시로 측정하기로 했지만, 실제 성능 증거는 아니다.
- **정답 세트는 사용자(문성원)가 표기**한다. 주관성이 있고, 2인째 독립 표기·일치율은 아직 안 했다.
- **블룸버그 알림과 직접 비교한 실험은 없다.** 차이를 말로만 설명했다.

### KIC 적합성
- **KIC 운용역이 실제로 '종목별 투자 가정'을 이렇게 관리하는지 검증하지 못했다.** 주식의 상당 부분이 패시브·퀀트·위탁일 수 있다. 7단계 방법론 전체가 이 가정 위에 서 있다.
- **판단 시각 07:30은 예시 사용자(문성원)의 습관 기준**이다. KIC의 실제 근무·회의 시각은 공개 자료로 확인하지 못했다(주 5일·일 8시간, 시차출퇴근 제도만 확인).
- 가정 장부를 처음 쓰는 **도입 비용**은 "기존 메모로 AI가 초안"으로 줄인다고만 적었다. 실제로 몇 분 걸리는지는 측정 전이다.

### 숫자·출처
- **13F 순위**는 ETF(iShares)를 포함한 순위이고, 같은 회사의 여러 주식 종류는 발행사명 기준으로 합산했다. 13F는 미국 상장 주식만, 분기 말 기준, 45일 지연.
- **공시 시각 분석(136건, 75%·70%)**은 8개사 1년치, 8-K/A 등 수정 공시는 제외했다. 다른 종목군에서 같은 분포가 나온다는 보장은 없다.
- 언론 보도에 의존한 숫자 — 운용자산 2,466억 달러, 외부 챗봇 월 3.7만 건, 위탁 745.8억 달러, 위탁 수수료 7.2억 달러 — 는 **원문 기사 전부를 직접 대조하지는 못했다.**
- **비용 추정(입력 약 1만 토큰, 월 수 달러 수준)**은 어림값이다. 평가 모델이 정해지면 실제 단가로 바꿔야 한다.

### 구현·운영
- **실제 화면이 없다.** 판정 카드는 설명용 목업이다.
- **모의투자 LLM 운영 기록이 짧다**(2026.11.3~, 첫 4거래일 판단 114회).
- **평가 모델(GPT/Claude), API 예산·키, 서버, 역할 분담이 미정**이다. 기존 개인 API 키는 사용 상한($95)과 11월 만료가 있어 대회용과 분리해야 한다.
- **SEC 자동 수집 방식:** SEC는 User-Agent에 연락처를 요구한다. 분석 중 연락처 이메일을 넣은 스크립트가 보안 정책으로 차단돼 브라우저로 대신 수집했다. 본선 구현 전에 수집용 연락처·방식을 정해야 한다.
